Engineering Robust
Multi-Agent Pipelines

Solving Semantic Drift, Reward Hacking, and Non-Determinism in Autonomous Software Teams with Mechanical Control Planes.

Audited Reference Architecture Grounded Citations: Primary Docs & Empirical Research Focus: Planning/Execution Split, Worktrees, & Sandboxed Egress
// EXECUTIVE_SUMMARY

Pairing autonomous coding agents across tools—one "architect," another "developer"—fails in three documented ways: semantic drift between intent and implementation, reward hacking against weak test suites, and coordination degradation across unconstrained multi-turn conversations. Prompt "skills," system instructions, and dynamic memory files (e.g., MEMORIES.md) cannot resolve these failures—they are probabilistic suggestions. Stability requires a mechanical control plane: frozen schemas, Git worktrees, read-only tests, compilers, and deny-by-default network egress.

01. Prompt Skills Are Not a Control Plane

Relying on prompt-level personas or dynamically injected rulebooks as an architectural control plane fails due to physical and statistical constraints:

  • Probabilistic Suggestions vs. Deterministic Gates: As context windows expand, model retrieval degrades across the center of the window, a phenomenon documented in Lost in the Middle (Liu et al.). Furthermore, system/user role separation fails to enforce a durable instruction hierarchy: models routinely deprioritize privileged directives under formatting conflicts or social framing, as proven in Control Illusion (Geng et al.). When an un-gated agent modifies an interface, it emits fluent rationalizations ("the mock required an extra parameter"). A compiler or schema validator does not negotiate—it yields a deterministic exit 1.
  • Physical State Isolation Cannot Be Prompted: Prompts cannot serialize multiple writers on a single inode. Git worktrees or remote VMs provide physical workspace isolation, preventing agents from clobbering each other's active trees mid-run. However, isolation only defers conflict resolution: the STORM framework (Liu et al.) demonstrates that physical isolation does not eliminate semantic merge conflicts across decoupled modules. Runtime contamination (mutating shared test databases or hitting live third-party endpoints) requires microVM boundaries with host-side proxying, not prompt rules. Shared mutable state degrades system integrity regardless of prompt quality—e.g., Sandipan Bhaumik's production case study where a stale 500ms cache read caused ~20% erroneous risk decisions across well-prompted agents.
  • The Context Pollution Tax: Accumulating past post-mortems and negative rules inside an agent's prompt bloats token overhead, increases latency, and shifts critical constraints into the low-attention center of the context window. While unconstrained broadcast topologies significantly elevate hallucination rates (Zhang et al.), structured state protocols like SEMAP (Mao et al.) cut coordination failures. Mechanical orchestration keeps prompts lean (spec in, code out), delegating enforcement to external gates.

02. Documented Empirical Failure Modes

  • Semantic Intent Divergence (SID): Architect agents reason over abstract interfaces, while implementer agents reason across local token buffers, leading to diverging assumptions as analyzed in Semantic Consensus (Acharya) and CodeCtx Context Synchronization (Baker). Worktrees prevent file overwrites, but semantic merge recovery remains non-trivial.
  • Reward Hacking & Test False Positives: In an audit of SWE-bench Verified, 28.5% of evaluated tasks had test suites weak enough to accept Docker-verified patches that were demonstrably broken (Rajan). Conversely, OpenAI's benchmark audit of 138 hard-fail problems revealed that 59.4% had flawed tests or ambiguous descriptions that rejected valid patches. Passing a test suite (exit 0) is a necessary mechanical signal, but not a complete oracle of correctness.
  • Same-Agent TDD Limitations: When an implementing agent writes its own test fixtures, it risks generating tautological assertions that pass without asserting (Autonoma). In an empirical evaluation on Martin Fowler's site, Birgitta Böckeler observed that same-agent TDD loops yielded negligible mutation improvements because agents frequently skipped or simulated the initial failing (red) step. Test fixtures must be independently authored in the planning plane and frozen prior to execution.

04. End-to-End Orchestrated Pipeline Flow

Phase Actor / Surface Generated Artifact Mechanical Verification Gate
1. Spec Planning Agent + Human OpenAPI / JSON schemas, typed interfaces, task manifest. Schema validation; explicit human approval gate; contract freeze by policy.
2. TDD Planning/QA Agent Unit and integration tests that fail against empty stubs. Independent runner verifies tests fail for the right reason (not missing files). Tests mounted read-only.
3. Isolate Control Plane (owt) Dedicated git worktree + restricted sandbox network. Physical filesystem separation; containment policy applied before tool calls.
4. Execute Execution Agent (Cursor) Concrete implementation source files. Local loop capped at 3 retries (team convention); tests remain read-only.
5. Evaluate Deterministic CI Build logs, mutation scores, AST type checks, overlap diffs. exit 0 baseline, mutation tests pass, Conflict Guard passes, Human PR review.

05. Sandboxed Egress Control & Mechanical Trust Rules

Unrestricted outbound internet during agent execution allows data leakage and live API fallbacks that bypass mocks. Docker Sandboxes (sbx) run inside microVMs with host-side credential proxying—secrets are never injected into the agent environment. Evaluation environments must enforce locked-down egress security defaults.

// SBX_CONTAINMENT_POLICY_SKETCH.YAML
# Illustrative Policy Sketch (Mapped to `sbx policy` / Cursor egress; not a vendor schema)
version: "1.0"
intent: "evaluation-time containment"
network:
  default_policy: deny
  allowlist:
    - host: registry.npmjs.org
      ports: [443]
    - host: pypi.org
      ports: [443]
security:
  credential_injection: host_proxy   # Sentinel swapped on host; secrets never enter microVM
  disable_raw_sockets: true
constraints:
  max_memory_mb: 4096
  cpu_limit: 2.0

The Four Mechanical Trust Rules

  1. 1. Treat Exit 0 as a Necessary Signal, Not an Oracle Natural language affirmations carry no evidential weight. Trust requires a mechanical exit 0 from compilers and linters, but passing tests alone do not guarantee semantic correctness.
  2. 2. Decouple Test Authorship The implementing agent must not author or alter test suites. Tests authored in Phase 2 must be mounted into the execution sandbox as read-only volumes.
  3. 3. Enforce Mutation Testing in CI A green test suite is necessary but insufficient. Automated mutation testing (e.g., Mutmut, Stryker) must verify that tests fail when semantic mutations are injected.
  4. 4. Evict on Budget Exceed If an agent exceeds its retry budget (e.g., 3 attempts) or fails static checks, automatically evict the worktree branch. Do not waste human hours debugging drifted context windows.
