Technical Whitepaper · 2026 Reference Architecture

Engineering Robust
Multi-Agent Pipelines

Solving Semantic Drift, Reward Hacking, and Non-Determinism in Autonomous Software Teams with Mechanical Control Planes.

Audited Reference Architecture Grounded Citations: Primary Docs & Empirical Research Focus: Planning/Execution Split, Worktrees, & Sandboxed Egress
// EXECUTIVE_SUMMARY

Pairing autonomous coding agents across tools—one "architect," another "developer"—fails in three documented ways: semantic drift between intent and implementation, reward hacking against weak test suites, and coordination degradation across unconstrained multi-turn conversations. Prompt "skills," system instructions, and dynamic memory files (e.g., MEMORIES.md) cannot resolve these failures—they are probabilistic suggestions. Stability requires a mechanical control plane: frozen schemas, Git worktrees, read-only tests, compilers, and deny-by-default network egress.

01. Prompt Skills Are Not a Control Plane

Relying on prompt-level personas or dynamically injected rulebooks as an architectural control plane fails due to physical and statistical constraints:

  • Probabilistic Suggestions vs. Deterministic Gates: As context windows expand, model retrieval degrades across the middle of the context [Liu et al., arXiv:2307.03172]. Furthermore, system/user role separation does not provide a robust instruction hierarchy: models routinely deprioritize privileged directives under formatting conflicts or social framing [Geng et al., arXiv:2502.15851]. When an un-gated agent modifies an interface, it emits fluent rationalizations ("the mock required an extra parameter"). A compiler or schema validator does not negotiate—it yields a deterministic exit 1.
  • Physical State Isolation Cannot Be Prompted: Prompts cannot serialize multiple writers on a single inode. Git worktrees or remote VMs provide physical workspace isolation, preventing agents from clobbering each other's active trees mid-run. However, isolation only defers conflict resolution: STORM shows that physical isolation does not eliminate semantic merge conflicts across decoupled modules [Liu et al., arXiv:2605.20563]. Runtime contamination (mutating shared test databases or hitting live third-party endpoints) requires microVM boundaries with host-side proxying, not prompt rules. Shared mutable state degrades system integrity regardless of prompt quality—e.g., Bhaumik's production case where a stale 500ms cache read caused ~20% erroneous risk decisions across well-prompted agents [Bhaumik, AI Engineer].
  • The Context Pollution Tax: Accumulating past post-mortems and negative rules inside an agent's prompt bloats token overhead, increases latency, and shifts critical constraints into the low-attention center of the context window. While unconstrained broadcast topologies can raise hallucination rates in some domains (such as travel planning: HR 0.658 vs 0.492) [Zhang et al., arXiv:2606.21666], structured protocols cut coordination failures [Mao et al., arXiv:2510.12120]. Mechanical orchestration keeps prompts lean (spec in, code out), delegating enforcement to external gates.

02. Documented Empirical Failure Modes

  • Semantic Intent Divergence (SID): Architect agents reason over abstract interfaces, while implementer agents reason across local token buffers, leading to diverging assumptions [Acharya, arXiv:2604.16339; Baker, CodeCtx]. Worktrees prevent file overwrites, but semantic merge recovery remains complex [Liu et al., arXiv:2605.20563].
  • Reward Hacking & Test False Positives: In a 49-task sample audit of SWE-bench Verified, 28.5% (14/49) of evaluated tasks had test suites weak enough to accept Docker-verified patches that were demonstrably broken [Rajan, arXiv:2606.16062]. Conversely, OpenAI audited 138 hard-fail problems (27.6% of the benchmark) and found 59.4% had flawed tests or descriptions that rejected valid patches [OpenAI, 2026]. Passing a test suite (exit 0) is a necessary mechanical signal, but not a complete oracle of correctness.
  • Same-Agent TDD Limitations: When an implementing agent writes its own test fixtures, it risks generating tautological assertions that mirror implementation bugs [Autonoma practitioner report]. In an exploratory evaluation on Fowler's site, Birgitta Böckeler observed that same-agent TDD loops yielded negligible mutation improvements because agents frequently skipped or faked the initial failing (red) step. Test fixtures must be independently authored in the planning plane and frozen prior to execution.

04. End-to-End Orchestrated Pipeline Flow

Phase Actor / Surface Generated Artifact Mechanical Verification Gate
1. Spec Planning Agent + Human OpenAPI / JSON schemas, typed interfaces, task manifest. Schema validation; explicit human approval gate; contract freeze by policy.
2. TDD Planning/QA Agent Unit and integration tests that fail against empty stubs. Independent runner verifies tests fail for the right reason (not missing files). Tests mounted read-only.
3. Isolate Control Plane (owt) Dedicated git worktree + restricted sandbox network. Physical filesystem separation; containment policy applied before tool calls.
4. Execute Execution Agent (Cursor) Concrete implementation source files. Local loop capped at 3 retries (team convention); tests remain read-only.
5. Evaluate Deterministic CI Build logs, mutation scores, AST type checks, overlap diffs. exit 0 baseline, mutation tests pass, Conflict Guard passes, Human PR review.

05. Sandboxed Egress Control & Mechanical Trust Rules

Unrestricted outbound internet during agent execution allows data leakage and live API fallbacks that bypass mocks. Docker Sandboxes (sbx) run inside microVMs with host-side credential proxying—secrets are never injected into the agent environment. Evaluation environments must use locked-down egress policies.

// SBX_CONTAINMENT_POLICY_SKETCH.YAML
# Illustrative Policy Sketch (Mapped to `sbx policy` / Cursor egress; not a vendor schema)
version: "1.0"
intent: "evaluation-time containment"
network:
  default_policy: deny
  allowlist:
    - host: registry.npmjs.org
      ports: [443]
    - host: pypi.org
      ports: [443]
security:
  credential_injection: host_proxy   # Sentinel swapped on host; secrets never enter microVM
  disable_raw_sockets: true
constraints:
  max_memory_mb: 4096
  cpu_limit: 2.0

The Four Mechanical Trust Rules

  1. 1. Treat Exit 0 as a Necessary Signal, Not an Oracle Natural language affirmations carry no evidential weight. Trust requires a mechanical exit 0 from compilers and linters, but passing tests alone do not guarantee semantic correctness.
  2. 2. Decouple Test Authorship The implementing agent must not author or alter test suites. Tests authored in Phase 2 must be mounted into the execution sandbox as read-only volumes.
  3. 3. Enforce Mutation Testing in CI A green test suite is necessary but insufficient. Automated mutation testing (e.g., Mutmut, Stryker) must verify that tests fail when semantic mutations are injected.
  4. 4. Evict on Budget Exceed If an agent exceeds its retry budget (e.g., 3 attempts) or fails static checks, automatically evict the worktree branch. Do not waste human hours debugging drifted context windows.
