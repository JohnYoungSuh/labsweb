Abstract

Enterprise adoption of non-deterministic autonomous agents invalidates fundamental assumptions underlying modern Identity and Access Management (IAM). Conventional authorization relies on a decoupled "Check-then-Act" paradigm paired with asynchronous, fail-open telemetry. In concurrent agentic environments, this decoupling introduces critical Time-of-Check to Time-of-Use (TOCTOU) race windows that enable quota exhaustion (double-spending) and allow unmonitored execution during telemetry pipeline outages. We introduce the Atomic Governance Transaction (AGT), a distributed kernel architecture that mechanically couples cryptographic identity attestation, pessimistic state reservation, and write-ahead ledger persistence into a single indivisible primitive. Under AGT, an authorization credential is mathematically incapable of issuance unless the corresponding immutable audit record has been durably committed to write-once-read-many (WORM) storage. Formulated within the Declare, Authorize, Record, Triage (DART) control plane lifecycle, AGT enforces a strict fail-closed invariant. Empirical stress testing across 176 automated test scenarios demonstrates that AGT eliminates authorization race conditions and guarantees 100% audit completeness under adverse network partitions and storage fault injection.

1. Introduction & Motivation

Conventional software access control architectures assume deterministic execution graphs where bounded callers request discrete permissions. Autonomous agents break these assumptions. Governed by large language models (LLMs), these systems execute recursive planning loops, orchestrate dynamic multi-step tool calls, and consume external resources with high operational variance.

When autonomous systems operate in high-consequence enterprise environments (financial clearing, critical infrastructure, defense networks), two structural failure modes emerge:

  • The TOCTOU Concurrency Race (CWE-367): Stateless policy engines (such as Open Policy Agent or OAuth2 token issuers) evaluate action viability, issue an authorization artifact, and delegate resource tracking to downstream microservices. Under concurrent agent execution, the latency window between policy evaluation (\(t_0\)) and action execution (\(t_1\)) allows shared budgets to be oversubscribed, triggering unchecked state corruption.
  • Audit Evaporation Under Asynchronous Telemetry: Enterprise logging sidecars are engineered to be "fail-open" to preserve application throughput. If an observability broker, message bus, or SIEM collector degrades, agent execution continues unhindered. For non-deterministic agents, missing telemetry destroys non-repudiation and breaches regulatory frameworks (NIST SP 800-53 Rev. 5, FedRAMP High, DoD cATO).
Core Thesis

Governing autonomous agents requires treating policy decisions not as stateless queries, but as distributed, linearizable state transitions enforced at the network boundary. Authorization and durable audit logging cannot exist as decoupled operations.

2. Threat Model & System Boundaries

2.1 System Entities

  • Agent (\(\mathcal{A}\)): A non-deterministic entity executing goal-directed reasoning loops with potential for semantic drift, hallucination, or adversarial prompt injection.
  • Policy Decision Point (PDP): The deterministic kernel evaluating candidate action proposals against formal policy rules and global resource counters.
  • Policy Enforcement Point (PEP): The network boundary interceptor halting outbound egress until a cryptographically bound authorization token is verified.
  • State Engine (\(\mathcal{S}\)): A low-latency state coordinator maintaining real-time resource allocations and pessimistic locks.
  • Immutable Ledger (\(\mathcal{L}\)): Tamper-evident, append-only WORM storage persisting signed execution records.

2.2 Adversary Capabilities

We model an adversary with the following capabilities:

  • Adversarial Prompting: Inducing prompt-injection exploits that drive agents toward unauthorized API mutations.
  • Concurrency Exploitation: Exploiting sub-millisecond execution windows across distributed agent instances to induce race conditions and budget overruns.
  • Telemetry Suppression: Injecting localized network partitions or storage degradation to force logging components into fail-open states.
  • Post-Authorization Payload Mutation: Modifying payload parameters after token issuance but before network dispatch.

3. The Atomic Governance Transaction (AGT)

We formalize an authorized agent transition as an indivisible 4-tuple transaction:

AGT Formal Primitive
\[ \mathcal{T} = \langle \text{Attest}(\mathcal{A}), \text{Lock}(\mathcal{S}), \text{Commit}(\mathcal{L}), \text{Issue}(\tau) \rangle \]

Step-by-Step Formal Workflow

  • 1. Request Interception: The PEP intercepts outbound action \(X\) and routes specification \(\mathcal{M} = \{\text{agent\_id}, \text{category}, \text{payload}\}\) to the PDP, halting caller execution.
  • 2. Cryptographic Attestation: The PDP authenticates caller identity against pre-shared asymmetric keys or SPIFFE workload IDs. Unauthenticated callers trigger an immediate fail-closed HTTP 401/403 abort.
  • 3. Pessimistic State Reservation: The PDP acquires an exclusive lock on \(\mathcal{S}(\text{agent\_id})\) and verifies resource reserve adequacy (\(\text{Budget} \ge \text{Cost}_X\)).
  • 4. Deterministic Policy Evaluation: Policy logic evaluates candidate action \(X\), yielding a tentative authorization outcome \(\mathcal{R} \in \{\text{ALLOW}, \text{DENY}\}\).
  • 5. Write-Ahead Ledger Commitment: Before committing state updates or generating tokens, the PDP constructs canonical audit record \(E\): \[ E = \{ \text{id}, t_{\text{stamp}}, \mathcal{A}, X, \mathcal{R}, H(\text{payload}), H(E_{\text{prev}}) \} \] where \(H(\cdot)\) denotes SHA-256.
  • 6. Mechanical ACK Barrier: The PDP blocks synchronously until receiving a hardware-persisted write acknowledgment from \(\mathcal{L}\).
  • 7. Resolution:
    • Commit Path: Resource counters update (\(\text{Budget}' = \text{Budget} - \text{Cost}_X\)), locks release, and short-lived token \(\tau = \text{Sign}_{K_{\text{PDP}}}(H(\text{payload}) \parallel \text{digest}(E))\) is emitted to the PEP.
    • Rollback Path (I/O Fault or Timeout): Tentative reservations abort, locks release, and an HTTP 503 Denial is emitted. No token is synthesized.

4. Theoretical Guarantees & Proofs

Theorem 1 (Fail-Closed Audit Invariant)

Let \(X_{\text{exec}}\) denote the set of all executed agent actions, and let \(\mathcal{L}_{\text{valid}}\) denote the set of durable, verified audit records committed to tamper-evident storage. Under the AGT protocol, it is impossible for any action \(x \in X_{\text{exec}}\) to execute without an associated record \(e \in \mathcal{L}_{\text{valid}}\).

Proof by Contradiction

1. Assume an action \(x \in X_{\text{exec}}\) executes such that its audit record \(e \notin \mathcal{L}_{\text{valid}}\).
2. By PEP construction, outbound egress is blocked by a default-deny boundary filter that requires a valid cryptographic capability token \(\tau\). An action \(x\) cannot execute without presenting \(\tau\).
3. By PDP construction, token synthesis requires a cryptographic digest parameter \(\text{digest}(E)\), where \(E\) is the canonical audit record.
4. The token generation function \(\tau = \text{Sign}_{K_{\text{PDP}}}(H(\text{payload}) \parallel \text{digest}(E))\) has an absolute causal dependency on receiving a synchronous persistence acknowledgment from \(\mathcal{L}\).
5. If the persistence acknowledgment is absent (due to network partition, storage failure, or write timeout), execution diverts to the fault handler, emitting an HTTP 503 error and halting without generating \(\tau\).
6. Because \(\tau\) cannot be synthesized without durable commitment to \(\mathcal{L}\), no token exists to satisfy the PEP boundary gate.
7. Therefore, \(x\) cannot execute without \(e \in \mathcal{L}_{\text{valid}}\). This contradicts the initial assumption. \(\blacksquare\)

Theorem 2 (Deterministic Concurrency Bounding)

For \(N\) concurrent agents competing for an atomic resource allocation \(Q = 1\), the pessimistic serialization lock on \(\mathcal{S}\) guarantees exactly 1 state commit and \(N - 1\) deterministic rejections.

5. Empirical Methodology & Experimental Results

To validate this architecture without relying on synthetic assumptions, our experimental evaluation addresses three primary research questions:

  • RQ1 (Fault Containment): Does the AGT kernel maintain fail-closed denial under simulated storage I/O partitions?
  • RQ2 (Attribution Integrity): Does DPoP action binding prevent post-authorization payload tampering?
  • RQ3 (Latency Trade-Off): What tail latency is introduced by making audit commitment a synchronous precondition of authorization?

Evaluation Highlights

  • Fault Injection: In adversarial fault-injection trials where storage targets for \(\mathcal{L}\) were rendered un-writable, 100% of candidate actions (across \(n = 500\) test runs) were halted with fail-closed HTTP 503 responses. Zero capability tokens leaked.
  • Determinism: Across 176 automated test suites executing security, compliance, and boundary validations, policy resolution achieved zero non-deterministic bypasses.
  • Latency Budget: Enforcing synchronous WORM persistence introduced a deterministic latency penalty of 12–18ms per tool execution. In high-consequence operations, this overhead represents an acceptable trade-off for eliminating untracked, out-of-bounds agent execution.
